## 设计校验与维护方式

在frontend目录执行：

1. 修改根目录DESIGN.md；设计值与页面原则一起维护。
2. `npm run design:generate`生成React和原生两份CSS；不手改生成文件。
3. `npm run design:check`核对规范和生成结果；`npm test`运行6项设计检查及前端测试；`npm run build`先校验，再类型检查及构建。

项目生成器使用上游公开lint接口，阻断全部error和contrast-ratio警告；未引用的色盘项是唯一允许的warning类别。当前22项属于图表、焦点、边框等未用于声明文字背景组合的设计值。它们不意味着所有浏览器颜色状态符合标准。`design:lint`供查看上游JSON报告；上游对比度warning退出0，不能单独作为合格门槛。

映射保留OKLCH、透明度及完整字体列表，亮／暗语义颜色必须成对；项目明确约定dark-前缀，不声称上游自动提供深色主题。浅色辅助文字略加深后，声明的浅灰背景组合达到校验门槛。危险按钮使用分主题文字颜色，主要按钮至少44px高。Web与打印规范分离，公式、生成文档与业务历史没有改写。

工具仅是开发依赖；现有锁文件旧包版本没有改变。Docker前端阶段携带规范与两份生成输入进行相同检查，运行阶段只携带构建产物及许可。GitHub工作流已有声明，本轮未push，不能登记远端CI通过。上游Apache 2.0与新增YAML许可已保留。
