## 入口决策（UX-36、UX-37）

DOC-IA：保留知识讲解与逐题解析两种内容类型，采用共同文档入口与工作区框架，保留旧 URL。依据是知识讲解有结论、定义、适用条件、知识依赖及学科论证；逐题解析有题目小问、作答步骤和方法关联。两者使用不同正式 schema、版本校验、生成完整性与核定依据，直接合并一个内容表单会损失含义；权限和输出历史可复用现有 CompanionWorkspace。后续文档导航按用途组织，共用成果入口，避免重复的选择/规则首屏。

PR-IA：家庭资料处理进度迁到“资料整理 → 处理进度”；复测区保留学习者计划与证据。旧 `view=progress&tab=materials` 转到资料整理对应入口，保留家庭范围；它不依赖学习者。迁移不会把资料完成数算作学习表现；保留原进度 API，便于兼容与验收。

## 候选能力定义与实施决策（UX-C01～UX-C04）

这些条目本轮交付定义与可行性评估，不把试验规则直接写成孩子的学习结论。基础题库行详情、状态与键盘操作已归入 UX-19；真实次数和已核对独立成功仍展示原有严格证据口径。

| 候选 | 可复算定义及验收条件 | 当前约束与本轮决策 |
| --- | --- | --- |
| UX-C01 正确率／趋势 | 统计单元为有效作答事件；同一事件只采用当前有效且已接受的答案评价。分母为同一学习者、实际日期区间、题目版本范围和提示条件内有明确答案判断的事件；未知、未评价、撤回不进分母，须另列数量。重复作答是不同事件，按题去重作为另一个指标，不能混用。分子是分母中答案正确的事件，不包含“生成答案”。比较窗口需同口径、同题集合或明确说明不同题集合，不输出因果性的复测效果。验收须覆盖重复、修订、撤回、未知日期和提示条件变化，并能回查分子／分母事件。 | 已有事件和评价可支持限定统计；题目可比集合、最低样本与展示策略尚无产品确认，现场也没有足够真实学习样本验证趋势含义。完成定义；本轮不启用百分比与趋势图。 |
| UX-C02 长期掌握／知识进展 | 以精确版本的知识／方法／题型关联确定目标题集合；逐次展示已接受的独立无提示证据和实际日期间隔。长期掌握必须另定多次证据、间隔、覆盖及反例撤回规则，不能从一次成功推断。关联、题目或评价修订后保留旧结论依据并重新核定。验收须覆盖多次独立成功、提示后成功、未知日期、不同题型覆盖及后续失败。 | 当前没有正式掌握判定规则、目标覆盖集合和持续真实复测样本。已实施次数、近期事件与条件回查；完成候选定义，本轮不增加掌握百分比或可信度分数。 |
| UX-C03 连续学习／阶段目标 | 有效学习事件仅指当前有效的真实作答，按已确认实际日期去重；系统日界采用服务端项目时区，未知日期单列，不用录入时间补齐。订正与复测可算有记录的一天，但不能表达学习时长。阶段目标须由人明确选择学习者、起止范围和精确目标集合，进度分子只能是满足目标条件的对象；生成、导出与资料上传不计学习天数。验收覆盖同日多次、跨日边界、未知日期、撤回与目标版本变更。 | 当前尚无阶段目标模型与用户确认的目标条件；可统计有记录日期，但不等于连续主动学习习惯。完成定义，本轮不显示连续天数徽章或目标百分比。 |
| UX-C04 规模化题库操作 | 先按真实数量与使用频率判断分页、多选、批量审核／关联是否必要。批量操作必须明确家庭、筛选、跨页选择和精确版本范围，先预览逐项结果；每项仍检查角色、核定依据与版本冲突，不以批量动作跳过审核。部分失败保留成功项及失败原因，重试幂等；只读成员无写操作。验收至少覆盖 100 项、跨页选择、筛选变动、关联过期与权限改变。 | 当前运行样本不足以证明批量流程的具体需求；已实施普通行详情、hover、标签、显式操作及资料分页查询。完成可行性评估；批量写入与自动审核延后，避免为规模化先扩大错误操作范围。 |

候选重新进入实施的条件：产品明确接受上述口径及具体目标／样本要求，取得匿名化的真实代表数据，并通过所列边界验收。届时追加正式任务，不把候选状态混入本轮 42 个主任务的关闭状态。

## 本轮交付与上线／回退方案（UX-35）

1. 本轮交付源码、必要回归、合成场景证据与更新后的主基线；不自动提交、推送或替换运行服务。当前基准是已核对的 `86d25ef`，新改动以工作区实际差异为准。
2. 提交前由主代理审查完整差异，运行相关前后端检查，核对文档链接与私人信息；只暂存授权源码与文档文本。原始照片、个人记录、生成 Word/PDF、验收截图、测试依赖和本机清单保留于忽略目录。
3. 发布输入须记录源码版本、锁文件、前端构建哈希与镜像摘要。本轮没有领域模型迁移；仍需在上线前复核迁移清单，不能由 UI 测试通过推断可直接生产切换。
4. 上线前执行现有配套备份流程，保留数据库与私有资料目录同一恢复点，并在隔离环境验证恢复、访问权限与旧文档读取。不可只备份源码或只复制本机清单。
5. 新镜像先在独立环境按本轮合成路径验收；现场切换另按用户授权执行。切换后检查家庭／学习者范围、真实档案、原图选区、旧文档、成员权限和模型关闭时的人工路径，不新增学习数据来冒充用户验收。
6. 回退时优先恢复此前已记录的镜像及前端产物，保持私有卷与数据库。若切换后有业务写入，先保留新恢复点；仅在确认数据库兼容或明确恢复范围后才恢复数据库，不能为回退 UI 静默丢掉新作答。
7. 本轮验收报告分别登记：已实现、自动工程验证、自动有界面浏览器／视觉核验、实际家庭反馈、Windows／macOS Word 实开、提交、推送与部署。未执行的层次明确写为未执行。

## 实际视觉检查中的修正

有界面浏览器先确认了 PDF 嵌入被页面框架保护拒绝；仅同源 PDF 的响应改为允许同源嵌入，并复验家庭权限。随后测试拦截器阻止了 Chromium 自带预览器的 `chrome-extension` 与 `chrome://resources` 本地资源，导致空白；已精确允许浏览器内置 PDF 的本地资源，站外 HTTP 仍禁止。普通有界面 Chromium 已实际显示合成家长答案的标题、题干、答案和公式；先前只有响应／空白的截图不计作成功。

知识来源检查另需等待并加载页面下方的懒加载照片；只等待可见 DOM 具有尺寸并不足以说明图片读取完成。最终检查会要求实际图片完整且有自然尺寸，再核对覆盖、缩放、旋转、保存及重新打开。题目录入页一度出现仅适用于知识定义的辅助入口；已限制为同时存在定义和排版字段的知识表单，19 项相关前端检查及最终构建通过。

知识修订页保留已有来源的精确引用，新选区域是追加输入；重开表单不应把旧引用重复送入新增列表。当前来源图片及其区域框此前也依赖被嵌入页移除的样式，现已统一补齐限宽、相对定位与区域覆盖。最终检查以数据库原图几何和重开后的实际框线位置分别验证，不改变原有追加／替换语义。

原生 200% 缩放的 DOM 检查确认 `devicePixelRatio=2`、CSS 视口为 960 像素，七域没有整页横向溢出且可聚焦。但 Chromium 自动整页截图按 CSS 尺寸截取放大后的像素，只保存了部分画面；这些截图不当作完整视觉证据。验收脚本已补充对独占 X11 虚拟显示器的实际 1920×1080 画面截取，随后由主代理查看七域真实缩放画面。

整页截屏也会短暂改变浏览器已绘制的视口。专项探针确认原生缩放本身正确；最终原生模式不调用整页截屏，等待字体及两帧绘制后直接读取独占显示器。主代理已查看最终七域画面及档案、题库原尺寸图，实际按钮、档案列表和导航未被截屏工具裁掉。
