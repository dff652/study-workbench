## 问题与改进目标

当前工程验收证明功能可以操作、数据可恢复，但不能证明入口容易找到、任务省力或真实家庭能顺畅使用。功能逐项拼装，再用卡片和折叠收纳，造成主业务隐藏、重复上下文、首屏任务出现太晚、宽屏空间不足。改进以完整任务和明确状态为单位，保留原图、正式历史、草稿、权限和数学内容。

| 已确认的问题 | 目标行为 | 首次验收方法 |
| --- | --- | --- |
| 主要功能收进“家长协助” | 六个业务入口常显，设置置底；按实际权限控制操作 | 从任意模块一次点击进入另一核心模块 |
| 家庭、学习者和页面说明重复占位 | 全局上下文只显示一处；模块标题与主要操作一行呈现 | 对比七入口首屏及具体记录归属 |
| 整个工作区受 `88rem` 限制 | 数据列表、原图和编辑区使用可用宽度；正文单独限宽 | 1280／1920／2560 截图和实际元素边界 |
| 卡片、折叠和长表单混用 | 列表与详情、对照编辑、模块 Tab 和步骤流程各司其职 | 三条业务闭环与多记录状态实际操作 |
| 技术术语与设计说明进入界面 | 用业务名称说明当前状态、原因及下一步 | 普通态、展开态、失败态和导入校验检查 |
| 保存和错误表达分散 | 草稿／正式保存、冲突／重试采用一致表达 | 切页、切 Tab、刷新、失败与迟到响应检查 |
| 缺少真实可用性证据 | 用实际家庭任务记录卡点、耗时和错误，再复测 | [真实小批次清单](web-family-trial-20261005.md)的实际反馈 |

## 统一页面方案

全局采用左侧导航、紧凑家庭／学习者上下文、模块标题与操作栏。模块内用 Tab 切换相关视图；同一列表的状态用筛选，必须同时核对的信息并排呈现。上传／核定／生成等有顺序的流程使用步骤和前置条件，不能将其伪装成自由切换的 Tab。

| 模块 | 主要布局 | 必须保留的业务行为 |
| --- | --- | --- |
| 学习总览 | 下一项任务、继续上次操作、少量摘要 | 学习动作可达；摘要不能将计划或生成答案算作掌握 |
| 资料整理／讲解编辑 | 资料列表；选定后原图与题面／解析编辑对照，历史和输出各有入口 | 选区与来源可回看；私人草稿与正式版本分开；v1／v2 历史可读 |
| 知识与题库 | 分类／搜索、题目列表、选中详情 | 知识／方法／题型双向关系、审核状态及题目来源 |
| 学习档案 | 历次作答列表或时间线、原图与评价详情 | 每次作答与评价独立保存；提示条件和未知项可见 |
| 进度与复测 | 复测计划／学习证据／资料进度 Tab；计划默认紧凑表格，详情按需展开 | 状态筛选、改期、取消、绑定实际作答、逐次历史；完成计划不自动证明掌握 |
| 文档中心 | 文件列表与预览；生成和下载集中 | 无答案练习与家长解析区分；PDF／Word／ZIP 与历史文件可用 |
| 设置 | 分类与相关设置分组 | 成员权限、模型关闭的人工流程、费用／外发说明、数据保留 |

这是结合本项目任务的设计取舍。参考 [Anki 的列表与编辑区](https://docs.ankiweb.net/browsing.html)、[Carbon 的 Tab 使用边界](https://www.carbondesignsystem.com/building-blocks/core/components/tabs/guidelines)与 [W3C Tab 键盘规范](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)，不引入这些项目的完整系统或新组件依赖。

### 并行规则

推荐 UX-02 阶段由三名 `luna6-worker`（`gpt-6-luna`）并行，主代理为第四个活动执行者。UX-01 期间共享部分由主代理统一完成，可先完成一个代表页面供三模块遵循。需要公共调整时，worker 先向主代理报告接口、选择器或样式需求，不自行修改公共文件。

每名 worker 的任务书必须包含：输入基线、允许修改的文件、输出、具体验收、不得回退他人改动，以及不提交／推送／部署。三个目录组互不重叠；API、路由、通用草稿 hook、权限、数据库、生成器和公共适配层由主代理拥有。业务逻辑调整先说明必要性及影响，不能以布局改版为由迁移数据或改写历史。

`features/materials/`、`content/` 与 `solutions/` 同属 UX-02A，避免资料和解析两名 worker 争抢流程。`features/workspace/page.tsx`／`page.css` 归主代理；B／C 各自模板里的样式不得变成另一套通用系统。已有源码、私有资料与运行实例均保留；新实现使用独立 worktree 和合成验收实例，不以线上学习记录作为自动测试写入目标。

主代理在并行结束后阅读完整实际 diff，检查共享契约、联动、边界与数据语义，独立跑必要验证。worker 未结束时不让另一个可写 agent 改其文件；独立 verifier 只读应用源码与构建，写自己的忽略证据目录，不代替主代理验收。

## 新增产品验收门槛

以下为**本次提出、需要逐项实际测量的门槛**，不是通用行业标准。已通过的本机范围见 [体验验收](reviews/web-ux-20261005.md)，第 9 项真实使用仍待反馈。

1. **任务可发现**：六个业务入口常显且一次点击可达；设置可直接进入。记录、资料、练习、讲解各有清楚动作，不依赖“家长协助”折叠。
2. **首屏与空间**：在 1280×800、1920×1080、2560×1440 的常规状态中，主要任务及操作起点出现在页面顶部 220px 范围；1920／2560 的列表与对照工作区占用至少 85% 的可用主区宽度。正文可以单独限宽；长名称、错误和放大文字允许自然增高，不能为指标裁掉内容。
3. **密度与数量**：默认普通记录行目标 40～48px，长题干自然增高；用 0／1／20／100 项合成记录检查阅读、检索和分页。保留服务端全量检索，不只搜索已加载的一页。大表可局部滚动，不能使整页横向越界。
4. **上下文正确**：家庭与学习者全局各显示一处；具体记录归属不一致时明确提示并正确处理。只读、空家庭、多家庭／多学习者、权限拒绝和会话过期均实际检查。
5. **导航与输入稳定**：切 Tab 保留输入与选择；URL 直达、刷新及前进／后退回到正确模块、记录和上下文。持久化范围区分家庭、学习者及记录；未上传文件仍需重新选择，不假装自动恢复。
6. **状态与错误**：草稿已保存、正式保存、保存失败、冲突和可重试状态清楚；主错误直接显示。普通／展开／失败态无设计说明、协议名、内部哈希／字段或原始对象；未知项、来源和校验强度保持。
7. **可访问性**：Tab 有名称、选中态及正确 panel 关系，支持方向键、Home／End 与激活；异步较慢的面板使用手动激活，焦点不能消失。主要操作无须悬停即可完成，明暗主题对比与现有窄屏回归检查通过。
8. **业务可信**：原图到题目、题目到无答案练习、讲解编辑到文档、作答到评价／复测／报告实际走通；原图、历史、权限、草稿冲突与来源未知规则保持。布局改动不以隐藏未完成条件伪造成功。
9. **真实使用**：按 [小批次清单](web-family-trial-20261005.md)完成真实家庭任务，记录起止点、耗时、卡点和需要帮助的地方；按结果修复再复测。合成测试及图片提案均不能代替该条。

验证随实际变化选择：前端重构执行相关组件测试、完整前端、类型检查／构建及浏览器任务；模板变化检查实际 HTTP 表单、错误与嵌入工作区。若修改后端逻辑、公式、生成器或数据契约，补做对应专项；没有这些变化时不重复宣称运行全部后端、排版或恢复。提交 review、push／合并和目标服务升级分别留事实回执，不能用路线图自动扩大当次授权。
