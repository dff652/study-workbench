# 模型草稿服务配置

模型任务默认关闭。任务由已登录且属于同一家庭的成员明确选择来源后排队；只有家庭所有者能追加模型配置版本。模型输出始终保留为建议，应用操作也只创建 `Origin.AI` 草稿，不接受或发布内容。变式任务须由原创建者应用，以保留来源归属；家庭所有者仍可在之后独立复核生成的题目草稿。

## 服务端设置

- `SWB_MODEL_API_KEY`：固定的服务端密钥环境变量。网页不收集密钥，数据库配置和任务快照也不保存密钥。
- `SWB_MODEL_ALLOWED_HOSTS`：逗号分隔的 HTTPS 主机名白名单。配置表单可保存 HTTPS 地址，但 worker 在发出请求前还会验证主机白名单；所有 HTTP 重定向都会拒绝。
- `SWB_AI_ALLOW_TEST_HTTP` 与 `SWB_TEST_OWNER`：仅用于开发环境的本机合成测试。生产模式不接受 loopback HTTP；不要在部署环境启用测试开关。

在家庭的模型配置页面填写兼容 Chat Completions 地址、模型标识、连接路径（直连供应商／网关／未知）、上游状态及名单、供应商留存说明或明确未知、外发范围、超时、输入/输出上限和预算。密钥须通过部署环境提供，不要写入源码、配置表单、任务日志或命令行参数。启用计费网关时填写输入和输出单价；零价格只有在确认网关非计价时才应标为非计价。启用图像区域外发时，每次调用还需配置正数的保守固定预留费用。

上游或留存状态选择“已知”时，必须填写对应内容；选择“未知”时保存为显式未知。启用远程调用前，所有者必须亲自勾选页面中的外发确认框。配置记录确认者账号和时间；服务端不会从 `cloud_enabled`、默认值或旧记录推断同意。每个启用远程调用的新配置都要求再次核对并确认；新增上游、更换路径或扩大外发范围也必须新建并确认配置版本。任务会固定供应商／网关、路径、上游、留存说明、完整外发范围及确认者／时间快照，可在任务详情中查看。

迁移前的配置和任务没有这些确认字段。数据库迁移为旧配置增加可空字段，不更新其追加记录；空值表示没有新确认。旧配置不能再排队或执行云任务。需要继续使用时，由所有者在页面追加一份新配置、明确填写已知信息或选择未知，并手动勾选确认框。后台在排队时以及每次真正发出外部请求前都会检查最新启用版本和任务快照；若配置已关闭、被新版本替换或确认不匹配，任务会在外发前失败并释放未使用的预算预留。带完整新确认快照的任务若在发送门槛前取消，会释放预留；通过门槛后可能已经发送，结果未知时保留预留。迁移前缺少该快照的旧运行保守记为未知，不能证明尚未调用。已开始的网络请求无法撤回。

`reviewed_text` 仅允许外发所选的当前已发布题目、知识和方法文本。`selected_regions` 才能附加用户明确选择的图像区域；服务从原图坐标裁切并重新编码 PNG，不改动原始图像。评价任务只允许指定一个有效作答；答案文本默认不外发，需单独勾选确认，手写图片也需逐区域选择。模型提示不会包含家庭档案姓名。

同一次任务的裁图合计最多 8,000,000 像素、PNG 字节合计最多 4 MiB，完整请求最多 8 MiB；超限在外部调用及预算预留前拒绝，须减少区域或重新框选。不会自动缩放或改变原图。只有评价任务显示答案文本勾选项，其他任务携带该项会被服务拒绝。

图像任务先按配置的固定金额预留，收到有效用量后，以“token 用量按单价折算金额”和“固定预留”中的较大值记入费用估算。超过预留的用量不会被吞掉，并会减少后续可用预算；未知结果继续保留预留。固定预留应依据供应商图像计价人工设置，它与返回用量都不保证等同供应商最终账单。

## 后台 worker

worker 与网页进程分开启动，并使用同一受控服务端密钥和数据库环境：

```sh
python scripts/run_model_tasks.py --watch
```

可以用 `--once` 执行单个已请求任务。worker 每轮先将过期租约标记为 `failure_unknown`，然后按队列顺序处理一个任务。外部请求期间不持有数据库事务锁；超时或进程中断的结果不会自动重试，未知费用预留会保留以避免重复计费。仅任务编号、状态和错误码写入标准输出，不写入响应内容或密钥。

## 限制

接口只接受封闭的 `study-workbench.ai.v1` JSON 结果，拒绝拒答、截断、未知来源、未知工具、重复 JSON 键和超大响应。算术检查在本地运行，模型不能执行代码、任意网络或文件访问。通过结构检查只表示数据形状有效，不表示学习内容正确；教师或家庭所有者仍需核对题干、来源和评价依据。

变式响应的目标方法必须来自任务实际选中的方法修订集合；同一请求中选中的题目或区域 ID 不能冒充方法通过结构检查。

## 离线基准与后续人工验证

`tests/ai/fixtures/development.json` 与 `holdout.json` 是纯虚构基准样本，不含真实照片、作答或身份信息。两集使用不同的 `source_page_id`、样本和修订标识，分别覆盖 question、knowledge、assessment、variant，并包含空白、不可读、未知作者、课堂笔记及提示后完成等情况。运行离线校验：

```sh
.venv/bin/python scripts/verify_model_baseline.py
```

脚本只检查数据集隔离、未知标记及 `study-workbench.ai.v1` 正反向结构探针；不访问数据库或模型供应商。结果写入被 Git 忽略、权限受限的 `artifacts/model-baseline/<id>/verification.local.json`。报告固定标注 `real_model_tested=false`，不会把结构探针计作准确率或质量结果，也不估算模型费用。

真实模型质量和费用验证留待所有者手动配置并单独决定。开始前先在隔离的本地测试家庭中用虚构内容重建样本，不上传真实照片或个人记录；通过 UI 创建配置，核对 HTTPS 主机白名单、固定服务端密钥、输入与输出限额、调用上限及小额批次预算。密钥只由运维安全地注入 `SWB_MODEL_API_KEY`，不能放在聊天、命令行、表单、数据库或报告里。先单独运行 development 样本并记录问题；冻结配置与提示后再运行 holdout，避免依据保留集调参。基准脚本不会发起模型调用，也不新增供应商调用入口。

每个实际任务以 case ID 记录：运行时间（UTC）、数据集分组、供应商和模型、配置／提示／schema 版本、输入与输出 token、服务估算费用、供应商账单费用、人工复核结果，以及每个未知项是否仍为未知、是否出现无来源推断。费用估算不是账单；另外检查提示后完成与独立作答是否被区分、不可读是否保持未知、未知作者是否被猜测、课堂笔记缺项是否被补成事实。按 development 与 holdout 分别保留结果和异常，不把结构通过写成准确率，也不把一小组样本汇总成泛化质量结论。真实测试记录应明确 `real_model_tested=true`；当前离线报告不会被自动改写成该状态。
