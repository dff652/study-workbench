# 需求独立评审记录 v0.1

日期：2026-10-01。评审对象为需求与 API／agent 可行性文档。以下行号均指首次评审快照（修订前）；主代理后续修改可能使行号移动。

## 评审范围

重点检查需求可追踪性、验收条件、家庭资料外发、题目区域与版本、作答证据、agent 权限及预算边界，以及 M1 范围是否适合进入数据契约。评审不是运行验收，也不代表 OCR 或模型效果已验证。

实际阅读：[AGENTS.md](../../AGENTS.md)、[README.md](../../README.md)、[DEV_STATE.md](../../DEV_STATE.md)、[requirements.md](../requirements.md)、[llm-agent-feasibility.md](../llm-agent-feasibility.md)、[implementation-plan.md](../implementation-plan.md)，并按需对照[assessment-and-roadmap.md](../assessment-and-roadmap.md)与[source-inventory.md](../source-inventory.md)。

## 主要发现

### P1-1：模型外发需要可执行的家长确认与撤回场景

**位置：** [requirements.md 第 93–97 行](../requirements.md#L93)，尤其 AC-19 第 97 行；[llm-agent-feasibility.md 第 91–99 行](../llm-agent-feasibility.md#L91)。

**场景与影响：** 家长首次启用云模型，或从人工核对文本改为发送题目照片时，AC-19 要求外发范围可配置、可说明，却没有要求界面明确展示本次发送的资料、区域、文本、供应商及已知留存方式，也没有记录家长选择或之后关闭云处理的行为。家庭无法据此判断孩子照片或作答记录是否会离开本地。

**最小修订：** 在 AC-19 增加验收：首次启用及外发范围变化时，家长确认具体供应商和数据类别；记录确认版本与时间；允许停止后续外发。将应用可删除的数据与供应商可能保留的数据分别说明，不承诺文档没有依据的供应商删除能力。

### P1-2：区域坐标、来源引用与过期草稿需要统一到可追溯版本

**位置：** [requirements.md 第 31–36、51–56、70–76、93–95 行](../requirements.md#L31)；[llm-agent-feasibility.md 第 69–83 行](../llm-agent-feasibility.md#L69)。

**场景与影响：** 一页照片含 EXIF 旋转，经旋转和裁切后框出题目；模型处理期间，家长又调整区域或题目文本。当前条文要求变换可回溯、草稿带来源引用、旧结果不得覆盖新版本，但未规定区域坐标相对哪一张图、引用指向什么版本，或哪些输入变化必须令草稿过期。数据契约可能因此把坐标、引用和“当前草稿”解释成不同含义。

**最小修订：** 在 AC-02 明确区域坐标的基准图及变换回溯要求；在 AC-06／AC-15 明确每个草稿保存其题目、区域和模型配置版本引用，任一依赖版本变化后只能显示为过期草稿，不能接受为当前版本。增加一条旋转／裁切后仍能定位原图区域的验收场景。

### P1-3：作答来源与“独立”判断应作为不同证据记录

**位置：** [requirements.md 第 40–43、54、59、75 行](../requirements.md#L40)；[llm-agent-feasibility.md 第 19–20 行](../llm-agent-feasibility.md#L19)。

**场景与影响：** 同一张正确答案照片可能是孩子独立完成、提示后完成、抄录课堂笔记，也可能无法确认作者。AC-04 列出若干类别，AC-09 要求独立性与提示，但数据对象没有明确把“谁的作答／证据来源”与“完成时是否受提示”分成两个判断；若只记录一个独立性状态，之后无法说明判断依据。

**最小修订：** 明确来源由家长记录，分开保存作答来源、提示情况、观察者及证据引用；允许来源或独立性为未知。增加“正确课堂笔记不能计为独立复测成功”的验收例，并禁止模型依据字迹或答案对错补填来源。

### P1-4：预算验收应覆盖并发预留和费用不确定状态

**位置：** [requirements.md 第 61、95–97 行](../requirements.md#L61)；[llm-agent-feasibility.md 第 75、85–89 行](../llm-agent-feasibility.md#L75)。

**场景与影响：** 单题限额、每批／每月预算、并发预留和供应商响应丢失后的可能重复计费，已在可行性文档中提出；AC-11／AC-18 当前只明确预算耗尽和调用次数超限应被拒绝，没有明确两个同时开始的任务不得分别消费同一笔剩余额度。提案中的 6 次模型请求、8 次本地工具调用和 180 秒也尚未经过性能或费用基准。

**最小修订：** 在 AC-18 增加并发任务共享最后一笔预算额度的反例，验证服务端预留后最多允许预算范围内的调用；将估算费用、实际用量和费用未知状态分开记录。把上述调用数明确标为初始可配置上限，注明上线值待基准与预算确认，不作为已验证承诺。

### P2-5：M1 的 P0 完成门槛覆盖面偏大，缺少首个家庭试用的分段条件

**位置：** [requirements.md 第 23–25、51–64、108–110 行](../requirements.md#L23)；[implementation-plan.md 第 20–32 行](../implementation-plan.md#L20)。

**场景与影响：** M1 一次要求上传及图像变换、题目与区域版本、AI 草稿和数学检查、导出、作答记录、预算、备份恢复、登录安全、取消与失败恢复及整套验收。实施计划虽将任务分阶段，最终 M1 门槛仍把这些 P0 全部绑定；家庭可能要等到模型和恢复路径齐备后才能验证人工整理流程是否省时。

**最小修订：** 保留各项需求，但将“可开始家庭试用的人工流程”与“启用模型后的 M1 完成”分成两个验收门槛，列明前者必须具备的上传、核对、导出、作答证据和恢复能力；AI 效果、时间节省和修订成本仍以家庭样本实测，不预设准确率或学习提升。

## API 与 agent 边界检查

可行性文档把供应商文档描述的图片输入、结构化输出和工具调用，与本项目识别正确率、数学正确性及作答掌握判断明确区分；OpenAI、DeepSeek 与 Qwen 的支持范围按具体端点／型号核对，DeepSeek strict 工具调用还标注 Beta 条件。官方来源由主代理另行核对；本评审未独立请求 API，也未上传照片、运行识别基准或部署 agent。官方能力只说明接口可用，不证明本项目照片效果、费用或延迟达标；这些均待后续授权配置与样本验证。

agent 权限边界总体清晰：工具只提交受服务端校验的请求，不提供任意 shell、SQL、文件系统、外网或直接批准题目；模型建议需家长接受，数学检查范围受限。AC-17／AC-18 已覆盖迟到响应、越界图片、未知工具、跳过审核及超预算等反例。需要补足的是上述并发预算验收和输入版本过期条件，而非新增自治 agent 或通用框架。

未发现需在本轮改写的范围性事实错误：文档将 23 张照片、61 道编号题、81 条索引和五份 PDF／Word 样本说成现有资料，并明确索引不是完整 OCR 题库；已有资料清单还区分了旧输出页数和当前实现状态。没有运行测试或重新检查数学及版式。

## 结论

建议完成 P1-1 至 P1-4 的最小文字修订后进入 A1 数据契约；区域基准与版本过期、作答来源与独立性、并发预算是契约必须保留的语义。P2-5 可由主代理决定是否先拆分试用门槛。本文是文档评审结论，不是应用、接口、agent、OCR 或备份恢复的运行验收。
