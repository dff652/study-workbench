# 功能清单与需求覆盖说明

版本：v0.2，2026-10-01。此清单说明产品应提供的能力，不表示功能已经实现。详细验收以[产品需求](requirements.md)为准。

## 1. 两项核心需求是否包含

**两项均为产品核心功能。** 第一条主线组织“学什么、有哪些题”，第二条主线记录“怎样作答、有哪些变化证据”。上传、OCR、API／agent、导出与备份是支撑模块；首版同时覆盖两条主线的基础能力。

| 用户需求 | 覆盖结论 | 本次明确的范围 |
| --- | --- | --- |
| 生成知识库或题库，建立知识点地图／图谱，关联题型和题目索引 | 包含，并在 v0.2 补成独立要求 | 知识库和题库分别管理；知识点、公式、方法、题型与题目可多对多关联；地图节点与具体题目可互相查找。首版采用基础地图、分类树和关联列表，复杂图谱展示后续增强 |
| 手写答题评价，建立档案并跟踪 | 包含，并在 v0.2 补成独立要求 | 评价可见解题过程并引用原图证据；学习者档案保存历次作答、订正、提示、复测和评价。首版提供历史记录；长期趋势、复习建议和综合报告后续增强 |

v0.1 已有六组方法地图、手写证据与作答记录，但没有充分写明独立知识条目／题型、结构化过程评价和个人档案视图。v0.2 用 FR-15～FR-18、AC-21～AC-24 补齐这些要求，不能将它们说成早已完整定义或已经开发。

实施建议为“成熟组件＋现有成果＋定制核心业务”。功能清单规定要交付什么，不要求每项从零编写；复用项也需通过同样的审核、来源及历史追踪验收。逐模块边界见[开发与复用评估](build-vs-reuse-assessment.md)。

## 3. 知识和档案如何关联

知识点／公式 ↔ 解题方法 ↔ 题型 ↔ 具体题目 ↔ 历次作答 ↔ 评价与复测。

这些关系支持多对多，不假定一道题只涉及一个知识点。六组方法是初始分类入口；知识点和题型有独立条目，新题型可先标未分类，不能强行归入既有分类。

示例：分数运算知识 → 裂项方法 → 两因子倒数和题型 → 关联题目 → 某次作答遗漏系数的已审核观察 → 后续换数或改变步长的复测记录。这个例子说明产品关联方式，不是对孩子新增的掌握判断。

知识地图表示学习内容的关系；个人档案表示目前有哪些学习证据。笔迹正确、接触过相关内容、在提示下完成和独立完成不能合并成同一个“已掌握”状态。

## 4. 使用建议

- 同时保留正确题和错误题，便于比较什么条件下能独立完成、什么变化会出现问题。
- 评价落实到具体方法和步骤，例如遗漏系数或末项符号；保留“无法判断”，避免用笼统的能力标签代替证据。
- 练习材料与家长答案分开，先留下独立作答，再给提示和例题，防止档案混淆不同帮助程度。
- 复习结合少量变式、间隔后的再次练习，以及让孩子解释方法适用条件。间隔安排、例题与独立练习交替、提问解释理由有相关研究支持，但本工具对个体的效果仍需观察。[IES 学习实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)
- 首版先把来源、索引和历史记录做准确，用家长整理耗时及实际复测记录检验价值。复杂图谱展示和更多模型按实际需要增加。
