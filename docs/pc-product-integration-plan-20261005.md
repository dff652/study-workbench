## 2. 一个工作台与左侧导航

所有业务入口使用统一 React 页面框架。点击左侧导航后只切换主内容区，侧栏、顶栏、当前家庭及适用的学习者上下文保持；不打开另一套业务页面，不用 iframe 包装旧页面。具体记录有可恢复的地址，支持刷新、浏览器前进／后退和直接打开。

| 左侧入口 | 主内容区与二级功能 | 原入口归属 |
| --- | --- | --- |
| 学习总览 | 待核对、待重拍、待复测、最近文档和已有证据统计 | 当前总览与进度摘要；统计均来自正式记录 |
| 资料整理 | 资料集、照片顺序、整页分区、原图与内容核对、整理进度 | 资料页、选区、旋转／派生处理、整理任务 |
| 知识与题库 | 知识点、方法、题型、题目、双向关联与来源 | 原知识地图；拆题／合题进入题目操作菜单 |
| 学习档案 | 学习者切换、逐次作答、笔迹待确认记录、评价、订正历史 | 原档案、作答记录、来源观察及评价页 |
| 进度与复测 | 资料整理进度、学习证据、复习计划、完成记录 | 当前进度及原复习页；计划完成不等于掌握 |
| 文档中心 | 五册、逐题解析、按讲／合集、预览、下载和生成历史 | 原打印、快照、报告；逐题解析为新增能力 |
| 设置 | 家庭成员、模型服务与费用、数据保留、帮助、关于与更新 | 原成员、模型配置、数据管理及版本卡片 |

算术复算进入答案编辑；讲义勘误进入题目详情；教学图进入题目／解析编辑；实际用时在整理任务中记录。它们仍有页面地址和来源回看能力，不单独占据一级导航。原图、评价和历史详情在工作台内打开；下载文档是显式下载动作。

普通页面显示题号、题目摘要、姓名／昵称、日期、中文状态和“查看原图／修改记录”。家庭 ID、请求键、配置 ID、源码摘要、schema、原始错误码和公式 JSON 不作为普通正文或输入要求。模型名称、费用上限和外发范围继续显示，因为它们影响用户选择。技术诊断经权限控制单独查看。

账号菜单显示登录名与角色；单家庭默认进入该家庭，多家庭支持切换。版本号保留简洁入口，更新记录在“关于与更新”中呈现。无明确口径的掌握比例不展示虚构值，未知、未测、空白和看不清继续分别保留。

## 3. 将 skill 转成页面功能

目标流程：选择资料 → 整理题目、知识与解析 → 对照原图核对 → 选择输出并检查 → 下载。用户可以只生成逐题解析，不必创建学习者或生成五册；真实作答从学习档案单独记录。

| 实用功能 | 用户能完成的事情 | 当前基础与增量 |
| --- | --- | --- |
| 整理向导 | 选择资料、讲次和输出目标，看到下一步需要处理的内容 | 已有资料集与任务；补讲次组织和目标导向入口 |
| 批量选图与页序 | 一次选多图，逐张显示上传结果；失败项可重试，跨页题能关联多个来源 | 复用现有逐张上传与幂等规则，增加队列界面；不改变原图字节 |
| 原图对照编辑 | 左侧原图／选区，右侧题面、小问、单位、答案、公式和解析 | 已有题面／答案核对；补层级小问与解析编排，坐标由选区生成 |
| 逐题解析编辑器 | 填写“先想什么、本讲解法、其他解法、步骤与易错点”，保留每次修改 | 新增独立解析草稿；其他解法可省略，不强凑第二种 |
| 知识与方法关联 | 明确选择知识出处、主辅方法和适用题目，并回看原资料 | 复用现有知识关系；新增解析与方法的显式关联，不能从正文标题自动认定 |
| 图示核对 | 对照原图查看题面图、辅助线及解析图，修改有依据和历史 | 复用教学图能力；新增 companion PNG 资源适配，用途分别保存 |
| 待补清单 | 集中查看缺题干、缺单位、缺来源、看不清、待重拍等事项并定位原页 | 复用未知与整页状态，补跨题聚合和定位；不能把缺失自动填为正确 |
| 勘误与修订对照 | 比较修改前后内容、依据及受影响文档，生成新版本 | 复用讲义勘误／追加版本；区分印刷错误、命名调整和草稿修正 |
| 输出选择 | 选择逐题、按讲、整批合集，PDF／Word／ZIP，或既有五册 | 既有五册保留；接入 companion 三种组织方式，同一题目内容一致 |
| 全页预览与检查 | 查看目录、分页、公式和图示，跳转异常页并重生成 | 复用机器验证，增加可操作结果；机器通过与 Word 实开分别记录 |
| 自动保存与继续 | 保存编辑草稿，离开后回到原任务；失败后只重试受影响步骤 | 增加显式保存状态与冲突处理；自动保存草稿不自动确认正式内容 |
| 可选 AI 辅助 | 选择来源后生成转写／解析建议，在同页修改和确认 | 复用受控模型服务；关闭模型时可手工完成，不引入自主无限循环 |

先完成已有能力的统一入口，再接逐题解析和输出，最后补批量效率。搜索、分页和筛选随业务页面迁移保留。首轮不另建聊天平台、插件市场或复杂报表设计器。

## 4. 接入边界与已冻结契约

Workbench 继续保存正式题目、知识关系、作答及评价。skill 提供版本化编排、确定性渲染、验证与打包；SOP 作为整理规则和可选模型提示。用户无需填写 JSON 或运行 shell。

主代理已在 `swb.solution.v1` 冻结以下字段和映射；新格式使用独立适配器，不直接送入现有 v2 导入器：

1. 资料／讲次／题目／层级小问的稳定关联，以及来源页顺序、真实选区、缺失区域和单位未知。已有来源页必须明确映射；只有整图或未知区域时保持待补，不伪造精确坐标或认定题库完整。
2. 解析正文、步骤、公式和页面块的可编辑草稿，以及指向正式知识／方法的显式关系。当前 skill 的“本讲方法／其他方法”只有正文约定；Workbench 关系通过明确选择保存，不从文字猜测。编译到 skill v1 时使用其已允许的内容块，新增结构放在版本化的 Workbench 契约中。
3. companion 的来源 PNG、裁切图和辅助图独立校验。它允许 8 MiB／400 万像素 PNG；现有 v2 为 1 MiB 交换包、单资源 512 KiB、配对 PNG＋PDF／SVG，不能直接兼容。使用受控私有资源上传及引用，不把整份 PDF／Word 塞进 JSON，也不把 PNG 冒充配套矢量图。
4. 解析用途固定为家长答案；解析内容和图示不进入无提示复测。导入解析不创建孩子的 Attempt、Assessment 或掌握结论。印刷错误沿用独立勘误及依据，其他内容修正保留自己的类型。
5. 内容、来源、资源、工具、字体与输出快照的版本绑定；变化后相关检查重新判断。历史输出不可覆盖，同配方复用前重验；失败不得推进成功指针或删除原有成果。
6. 机器检查、内容核对、数学复核、PDF 视觉检查和 Word 客户端结果分别保存真实范围。页面聚合成“待核对／可预览／待检查／可下载”等可理解状态，不强迫用户操作内部工具阶段，也不把未验结果自动填为通过。

数学和富文本模块已有相同实现，但两仓库的 contracts、fonts、renderer 文件不同。接入固定提交及明确依赖，做兼容适配；不整体覆盖现有渲染器。真实模型由用户按既有决定配置测试，默认关闭。

## 6. 分工与首个切片

主代理负责共享导航／接口／内容契约、`frontend/src/api.ts` 与 `types.ts`、Django API／业务适配、资源与导出、测试证据、项目文档、完整 diff 和最终验收。

应用实施使用一个 `luna6-worker`（gpt-6-luna），按阶段承担 `App.tsx`、页面框架、路由与明确分配的 features／components／前端行为测试；不修改共享接口类型、后端、其他仓库或未分配文件。委派前明确输入输出和文件所有权，告知共享工作树中还有其他修改者，不得回退他人改动。后续切片复用同一 worker；本轮实施已启用一个 Luna6 前端 worker。

首个实施切片为 PC-01＋PC-02 的共享基础：主代理先提供统一导航定义、路由与展示字段、会话／角色和错误约定，worker 再迁移现有四个 React 页面、账号和版本入口。缺业务 API 的模块在后续任务中完整接入；不能用可点击但没有真实功能的菜单、iframe 或旧界面跳转宣称整体迁移完成。

首切片验收：现有四个页面无功能倒退；刷新、前进后退与当前资料／学习者范围一致；当前用户、退出和权限正确；版本与更新可达；原有列表、空态、加载、失败重试和并发保存行为通过。其他模块仍标为待迁移，整体界面完成依赖 PC-03～06。

## 7. 最终验收门槛

- 逐页登记列表、详情、新建／编辑、历史、弹窗、空态、失败、只读角色和过期会话；对原 48 种 PC 页面逐项标明新归属，不能仅以首页截图或 HTTP 200 作为完成。
- 在 PC 常用宽度 1280／1440／1920 下检查实际页面；导航、面包屑、表格、表单、按钮、提示和版本入口一致。知识库、成员及模型配置从主导航进入后保持同一框架，原图和记录详情也可回到原上下文。
- 普通界面不展示工程阶段编号、代码枚举、原始 JSON／哈希或要求输入数据库 ID。数学公式与图示使用实际可读预览，未知状态有具体原因和补充入口。
- 验证跨家庭隔离、只读权限、并发更新与重复提交；确认两条核心主线的双向来源、多次作答／多份评价、课堂／提示／独立区别以及讲义错误与学习者错误分离。
- 模型关闭时完成“上传→手工整理→核对→导出”；匿名 companion 样本包含跨页题、层级小问、未知单位／区域、图示和勘误。按题／讲／合集内容一致，PDF 全页目视及 DOCX 结构验证通过；实际 Word 未打开时继续标为未验。
- 主代理审查全部实际差异并独立执行相关验证。涉及新增持久化时补迁移与联合恢复检查；未修改持久化的纯界面任务不重复全套恢复。真实模型、家庭完整批次、客户端实测和外部交付分别记录实际范围。

## 实施中的适配决定

- 既有业务表单通过白名单、同源页面 API 复用校验及业务服务，只将过滤后的主内容放入 React 主框架；旧导航、旧样式和内嵌脚本不载入，不使用 iframe。坐标选择、页序等交互仅载入已声明的固定控制器。表单错误留在当前框架，权限、CSRF 和追加版本约束继续由服务端执行。
- companion 采用固定提交的纯内容校验／组织模块，以相对导入封装；原生渲染器增加独立 PNG 图示类型，不将 PNG 当作已有配对矢量教学图。继续使用既有字体、PDF／Word 工具链，旧 v1／v2 导入器保持独立。
- 本轮分阶段结果及最终验收分开记录；准确测试范围、逐页矩阵和交付状态见 [DEV_STATE](../DEV_STATE.md)。
