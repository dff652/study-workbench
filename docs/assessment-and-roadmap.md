## 1. 目标与范围

建设家长主导的家庭学习工具，将资料照片、题目、方法分类、原图证据和历次作答关联起来，减少整理时间，并为针对性复习提供依据。

初期服务单个家庭，保留纸上解题。家长负责资料审核和复习安排；孩子端只需清晰的练习、必要提示和独立作答入口。先观察家庭使用效果，再决定对外产品化投入。

首版优先包含：

- 登录、手机上传、原图查看、手动框题和题干核对。
- 题目与小题、六组主分类、辅助方法、来源回溯和查询。
- 分开导出孩子练习与家长答案，沿用现有重点标注和数学公式排版。
- 后续接入 OCR，所有识别结果先进入待审核状态。
- 后续记录独立作答、提示、错误步骤和延时复测。

初期不安排公开题库、多租户商业平台、向量数据库、复杂推荐算法或自动给孩子生成掌握百分比。题目数量尚少，先通过结构化分类与普通查询验证需求。

## 4. 默认技术方向

| 层次 | 建议 | 理由与待验证事项 |
| --- | --- | --- |
| 服务端 | Python／Django | 复用现有 Python 导出代码；内置数据模型、用户与管理后台 |
| 网页 | Django 模板＋HTMX，框选区配少量 JavaScript | 先满足上传和审核；复杂交互出现后再评估是否需要独立前端 |
| 数据库 | PostgreSQL | 题目、来源、版本和作答使用关系表；OCR 原始结果可使用 JSONB |
| 图片 | NAS 文件存储，数据库存位置与校验值 | 保留原图和派生版本，便于备份与恢复；不把所有图片直接塞进数据库 |
| OCR | 可替换接口；比较 PaddleOCR 与 Pix2Text | 先做相同样本测试，不预判最佳模型或 GPU 需求 |
| 导出 | 提取现有 PDF／Word 渲染模块 | 保留可编辑公式和重点标注，处理依赖及授权问题 |
| 后台任务 | 批量 OCR／导出由独立任务进程执行 | 到批量处理阶段再接 Celery 等成熟组件，避免自行编写复杂队列 |
| 部署 | 容器化服务，默认 Docker Compose；宿主设备与 NAS 存储路径待定 | Web／持久化就绪后执行 D1；CPU、内存、耗时和恢复尚未实测 |

技术参考：[Django](https://www.djangoproject.com/start/)、[HTMX 上传](https://htmx.org/examples/file-upload/)、[PostgreSQL JSON 类型](https://www.postgresql.org/docs/current/datatype-json.html)、[Celery](https://docs.celeryq.dev/en/stable/getting-started/introduction.html)。具体依赖版本在实施时选择并锁定。

## 5. 数据模型的必要边界

本节为早期摘要；最新实体与版本关系以[核心数据契约草案](core-data-contract.md)及需求第 5 节为准。知识条目、方法、题型、学习者与评价各有独立身份；历史作答固定所用题目修订，来源观察不强制变成作答。

| 对象 | 核心记录 |
| --- | --- |
| 来源资料与照片 | 资料名称、页序、原文件、尺寸、上传时间、校验值 |
| 题目与小题 | 完整题干、公式、父子题关系、版本、审核状态 |
| 题目图片区域 | 来源照片、坐标、区域用途；一道题允许多张照片及多个区域 |
| 方法分类 | 现有六组、细分技巧、主分类和辅助分类 |
| 识别任务与订正 | 引擎及版本、原始结果、错误信息、人工订正、审核人及时间 |
| 每次作答 | 时间、答案、过程、所用方法、是否独立、提示情况和来源 |
| 证据与复习 | 错误步骤、判断依据、复测题、提示记录和延时结果 |

必须保留以下区别：

1. 题干识别正确、手写答案正确、孩子独立掌握是不同判断。
2. 作答来源至少区分独立完成、提示后完成、抄录／课堂笔记、来源不明。本批不能区分来源的笔迹维持“来源不明”。
3. 原图保持原样；裁切、去笔迹和增强图为派生版本，能够回溯原图。裁切坐标需明确参照原图还是变换后的图像。
4. OCR 原始结果与人工修订分别保存。未审核识别结果不能自动成为确定题干或掌握证据。
5. 原讲义错误与孩子错误分开。已发现的整数裂项公式系数错误需要保留原文、正确版本和订正依据。
6. 只对有证据的步骤下结论；空白、擦除、看不清或来源不明保留未知，不自动归为不会。

## 6. 分阶段交付与验收

### A. 整理现有原型

R0 v0.1 独立评审及 v0.2 主代理补充、A0 文档评估已完成。A1a 已实现并验证，结果见 DEV_STATE；A1b-P 已获授权并实现持久化及审核事务子集，验收以 DEV_STATE 为准；真实导入和渲染仍按最新实施分工另行执行。

将可复用渲染能力独立出来，固定依赖、参数化路径，导出稳定的数据格式，解除 v3 对历史 v2 文件位置和固定文案的耦合。先保留历史输出，再生成新输出用于对比。

验收：

- 23 张照片及 81 条索引无遗漏、无重复，编号及六组数量一致。
- 缺失完整题干和区域坐标的记录明确标记，不能假装字段已经齐备。
- 从明确输入可重复生成文档，不依赖历史工作目录。
- 核对数学公式、内容完整性和 PDF 版式；Word 原生公式保留。未独立验证 Word 分页时明确说明。
- 保存依赖和字体来源，校验原始文件未改变。

### B. 最小 Web 工具

实现登录、上传、手动框题、题干审核、分类查询及打印。数据模型预留作答关系，首版不强求自动 OCR。

验收：家长可以完整处理一批资料；题目能定位原图；重复导入不会产生无提示的重复记录；错误上传能给出清晰结果；权限和备份恢复通过实际验证。

### C. OCR 辅助整理

接入候选引擎、待审核结果、失败重试及批量任务。先定义统一输入输出，再实现单一适配器。

验收：在相同实际照片上比较漏题、分式分母／指数／正负号错误、跨页处理和人工修订时间。现有索引只能辅助检查题目数量，不能替代完整题干真值；测试前须人工核对测试区域。未经审核的 OCR 不能直接改写已确认题目。

### D. 学习记录与复习

实现独立作答、提示、具体错因、变式练习和延时复测。用实际作答记录支撑复习建议，显示证据不足的情况。

验收：能够回看每次作答及其来源；课堂笔记不会被当作独立掌握；同一道题的订正和再次作答有不同记录；孩子题目与家长答案分开呈现。

进入对外产品化之前，再评估多用户隔离、运维成本、授权和持续使用收益。当前没有开发工期承诺，OCR 性能与家长修订成本仍未知。

## 7. Luna 分工与主代理验收

在用户授权的实施任务中，适合逐次交给 luna6-worker 明确且有边界的工作。主代理先确定输入、输出、文件所有权及验收方式；本次建项未启动 worker。

| 可委派工作 | 主代理保留的责任 |
| --- | --- |
| 提取渲染模块、参数化路径 | 完整 diff 审查、公式核对、输出对比 |
| 按固定数据格式实现导入 | 数据模型、重复导入和失败恢复验收 |
| 按固定接口实现上传审核页面 | 手机实际流程、权限和原图定位验证 |
| 实现一个 OCR 适配器 | 同批样本比较、错误归因和最终选择 |
| 实现明确的作答记录流程 | 学习判断边界、记录准确性和最终验收 |

worker 必须知晓自己并非唯一修改者，不能回退他人改动；遇到共享文件变更应协调适配。主代理需要检查完整实际差异、独立运行相关验证并走通流程，不能只接受 worker 的完成报告。既往只读 smoke 不能证明代码修改能力或本任务正确性。

首次评估提出的渲染模块提取仍保留。v0.1 需求独立评审已完成；本轮一个 luna6-worker 完成 A1a 离线契约子集，主代理已独立验收，尚未提取渲染。所有权和验收见[实施分工](implementation-plan.md)。

## 8. 对孩子学习的预期价值

可验证收益包括减少家长整理时间，以及按具体错误安排少量独立练习。支持间隔练习、例题与独立练习交替、解释解题理由；这些方向有教育研究支持，但不代表本工具已证明可以提高孩子成绩。参考：[美国教育科学研究院学习实践指南](https://ies.ed.gov/ncee/wwc/PracticeGuide/1)。

结合现有证据，优先观察：

- 步长变化后，裂项系数能否相应调整。
- 写通项时是否核对第一项。
- 抵消后末项符号、分母是否完整。
- 能否连接求和公式、倒数变形与裂项。

建议用 2～4 周家庭试用观察整理耗时、同类错误、换数后的独立完成情况，以及延时后能否解释理由。这是试用建议，不是经过验证的效果阈值。资料收集数量和 AI 给出的答案数量不作为学习进步指标。
