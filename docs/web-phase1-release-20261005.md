# 第一期 Web 产品范围与交付门槛（2026-10-05）

用户决定：第一期目标是 Web 端完全可用的产品；手机端开发放到第二期。先更新项目文档、提交并 review，再 push 和合并。源码交付与运行服务升级分别记录。

## 两期范围

| 阶段 | 产品目标 | 当前范围 |
| --- | --- | --- |
| 第一期 | 用户在电脑浏览器中完成真实学习与资料整理流程 | 七个统一入口，资料／题库／知识、讲解与下载、历次作答／评价／复测、权限、任务恢复、配套备份恢复及使用说明 |

已有窄屏适配、触摸帮助和 PWA 基础保留，现有宽窄屏验收记录继续有效；本轮不新增手机专项开发。Android／手机验收不作为第一期 Web 发布门槛。

原需求中的 M1a／M1b／M2 区分人工、AI 和学习增强能力，与本次按平台划分的第一期／第二期不同。FR／NFR／AC 编号保留；NFR-06／AC-20 的 Web 部分在第一期验收，手机部分在第二期验收。真实模型效果、费用及外发实测维持此前延期安排；第一期必须能关闭 AI 完成全部人工主流程，不能将离线通过写成真实 AI 质量通过。

## 后续顺序

1. **文档与源码交付**：更新平台阶段、第一期完成条件和未验边界；源代码与文档分别提交，检查完整待推送范围、隐私排除、冻结输入、链接和独立 review。
2. **push 与合并**：review 通过后 push `codex/pc-integration`，通过 PR 合并 `main`，回读远端提交与审查的内容一致；不 force push，不把合并当作部署。
3. **第一期运行交付**：另行执行目标服务的配套备份、空实例恢复、候选迁移演练、升级与实际 Web 验收。旧版本和配套恢复点保留，不能将旧镜像直接接到已迁移数据库。
4. **第一期真实试用与收口**：在电脑浏览器完成一小批真实资料到讲解／练习，以及作答到复测／报告；登记浏览器、实际日期、来源、未知项和问题。Word 实开与真实模型分别登记实测范围。
5. **第二期手机端**：在第一期收口后安排移动专项开发、Android 真机和 PWA 验收，不以既有 390 宽度截图替代真机通过。

本次交付动作不包含运行服务升级、真实模型付费调用、真实照片外发或 NAS 发布；这些步骤有明确输入、数据影响和验收记录后另行执行。
