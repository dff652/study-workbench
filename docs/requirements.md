## 1. 目标、用户与成功条件

为家庭持续整理数学学习资料，减少家长查找、转写和编排时间，使每条学习判断都能回到原题和具体作答。当前内容从五年级奥数开始，数据结构不把年级或孩子姓名写死。

| 用户 | 主要任务 | 产品边界 |
| --- | --- | --- |
| 家长 | 上传、核对、分类、打印、记录作答与安排复测 | 审核者；可以更正 AI 草稿及撤回判断 |
| 孩子 | 看简明知识总结、纸上独立做题、说明方法 | 首版不要求独立账号或开放聊天；孩子用材料与答案分开 |
| 系统维护者 | 配置存储、模型、预算、备份和恢复 | 单家庭部署，可由家长兼任 |

成功条件：资料能检索并追溯；重复整理耗时降低；复习依据实际作答而更新；停止使用 AI 后人工整理、查看和导出仍可用。学习效果需经家庭试用观察，不承诺成绩提升或给出未经校准的掌握百分比。

### 两条核心功能主线

1. **知识与题目组织**：知识库和题库、知识地图，以及知识点／方法／题型／题目的关联索引。对应 FR-03、FR-05、FR-10、FR-15、FR-16。
2. **作答评价与学习跟踪**：手写过程评价、个人档案、历次作答及复测。对应 FR-04、FR-09、FR-17、FR-18；FR-13、FR-14 在后续增强复习和学习汇总。

两条主线均为核心，首版 M1a 同时覆盖基础人工流程。上传、OCR、API／agent、打印与数据保障为其提供支撑；模型接入本身不能代替核心业务完成。无论采用开源功能、提取旧代码还是新开发，均须通过相同 AC。实现边界及候选依据见[开发与复用评估](build-vs-reuse-assessment.md)，本次不改变已有需求及验收编号。

## 2. 当前事实与首版范围

现有 23 张照片、61 道编号题、81 条小题分类记录和五套 PDF／Word 是资料样本。分类已人工核对，但完整可编辑题干、逐题框坐标和独立作答来源尚未齐备。五份 PDF 合计 29 页属于旧输出基线，不是任意未来文档的固定页数。

M1 首版包含 P0：资料上传和人工审核、知识库与题库、知识点／方法／题型／题目的基础关联地图、单一供应商的可选 AI 草稿流程、导出、手写过程评价、个人档案及逐次作答记录、可追溯性与预算控制。M2 包含 P1：变式草稿、复习安排、基于多次记录的学习报告；更复杂的图谱展示按使用需要再评估。

M1 分两次验收：M1a 验证人工整理、导出和作答记录；M1b 再验证 AI 草稿与有限 agent。M1a 可用于家庭试用，不宣传为已完成 AI 版本。具体验收划分见第 8 节。

不纳入 M1：公开题库、商业多租户、自由聊天辅导、无人审核的自动判卷、自动判断笔迹作者、全面数学证明、向量数据库和多个自治 agent 相互辩论。未来扩展按实测收益决定。

## 3. 用户流程

### 资料入库

1. 家长创建资料集，上传照片并查看逐文件处理状态。
2. 保存原图；旋转、裁切、去笔迹和增强生成可回溯的派生图。
3. 人工框题，或启用模型生成题目区域、题干和分类草稿；支持跨页合题、拆分与重新排序。
4. 在原图与文本并排界面核对题干、公式、题号及区域。题干和手写内容分栏。
5. 系统检查字段、引用和可支持的数学表达式；家长逐题确认。未确认条目不混入“已审核题库”。
6. 按六组方法检索，生成方法索引、知识总结或练习。导出显示内容版本和审核状态。

### 作答与复习

1. 家长选择已审核题目，导出无答案、无方法暗示的独立练习材料。
2. 孩子纸上作答；家长记录时间、过程照片、提示情况及是否独立。
3. AI 可生成带证据引用的错误步骤草稿，家长核对；看不清、来源不明或步骤不足时保留未知。
4. 家长按具体问题选择复测题；M2 才引入变式草稿、排期和多次证据汇总。

以下约束已整理为 [A0 核心数据契约草案 v0.1](core-data-contract.md)（2026-10-02，主代理起草及文档复核，未独立评审）。A1a 离线实现状态见 DEV_STATE；同日 A1b-P 已选择 Django／PostgreSQL 并实现持久化子集，实际状态见[持久化契约](persistence-contract.md)与 DEV_STATE，不改变本需求版本及 FR／AC 编号。

进入实现时遵循以下契约约束：

- `EvidenceRef` 包含原图 ID、SHA-256 和引用粒度。区域级引用必须有区域 ID／版本、坐标系及用途，统一使用原图像素坐标，派生图保留到原图的变换关系。旧索引可使用明确的整图级引用，区域字段为空并标记待补，不能伪造精确位置。来源检查核对对象归属、哈希、坐标界限和版本；来源存在不等于该来源足以支持结论，后者仍需审核。
- 题目草稿通过 `run_id` 记录所依据的题目、区域、分类规则及模型配置版本，配置快照包含实际供应商、模型、prompt 和 schema。应用草稿或接受审核时在同一事务内比较当前版本；任一依赖版本已变化则保存为 `stale`，不能覆盖当前题目。重新分析或家长明确迁移到当前版本后才能再次审核。
- 模型／prompt 更新使旧缓存不再用于新运行，但不会自动撤销此前人工确认的题目。旧人工审核结论保留为带版本的历史记录。
- 作答对应明确的 `learner_id` 和题目版本。区分实际作答时间 `occurred_at` 与录入时间 `recorded_at`；前者未知时可为空，不能用上传日期代填。独立性与笔迹作者分别记录，不能由其中一个推断另一个。
- 无法确认归属或发生时间的历史笔迹可先记作来源观察 `SourceObservation`，关联原图、题目和已知信息，不强制创建独立作答。家长确认归属后可关联作答，但保留原观察及确认者、确认时间。
- 知识地图表达知识之间及其与题目的关系；个人档案表达孩子的作答证据。两者用知识／题目 ID 关联，课堂中接触过某知识点不能自动变成“已掌握”。
- FR-16 的基础关系包含知识条目引用、方法应用和题型归属；先修依赖、易混关系和复杂图谱推理可后续细化，不要求首版建设专用图数据库或推理引擎。AI 新建条目和关系也须审核。
- 手写评价不是字迹美观评分。不清晰导致无法辨认时标记证据不足；不据单次对错给孩子贴能力标签，也不将未经核对的模型评价合并为档案结论。

约束：存储位置与业务 ID 分开；原图不变；题干修订不重写历史作答；删除资料前展示被引用的作答和导出，保留可恢复归档方式，永久清理由明确动作触发。运行日志记录必要元数据和简短依据，不要求模型隐藏推理链。

## 6. 模型与 agent 的职责

- 大模型适合生成题干、分类、解析、勘误或观察草稿；人工确认及程序校验决定其是否可使用。
- agent 在限定任务内选用读取题目、获取区域、查方法和数学检查等工具。业务状态、权限、预算和正式数据写入由服务端控制。
- 首版只实现一个有限 agent 流程，首个供应商经能力测试后选定。多供应商接口不等于同时实现所有供应商。
- 同一模型或另一模型的复核仅是辅助意见；数学工具与人工审核保持独立责任。
- 技术细节和候选见[可行性评估](llm-agent-feasibility.md)。

| NFR-01 | 数据来源、审核与过期结果控制 | AC-15：AI 运行期间题干被修改，旧结果只能保存为过期草稿；不能覆盖当前版本。回看记录可确定产生时使用的题目版本 |
| NFR-02 | 登录、上传与资料访问 | AC-16：未登录不能读照片或答案；上传验证实际文件类型、大小和解码像素上限；路径和对象 ID 均经授权校验，不接受模型提供的任意文件路径或 URL |
| NFR-03 | 失败恢复与任务幂等 | AC-17：模拟超时、429、无效结构、worker 中断、取消后迟到响应；正式数据不重复落库，已完成步骤可恢复；外部请求结果未知时不声称绝对不会重复计费 |
| NFR-04 | 有限工具与调用上限 | AC-18：伪造“跳过审核”的题面、未知工具、越界图片 ID、超预算和超调用次数均被服务端阻止；单题初始工程限额见可行性评估，不接受模型自行提高 |
| NFR-05 | 数据外发与密钥管理 | AC-19：供应商及数据外发范围显式配置；只发送必要区域／文本；密钥在服务端受保护配置中，网页、日志、Git 和导出无密钥；原图、模型响应及监控 trace 的存储范围可说明 |
| NFR-06 | 可用性与性能记录 | AC-20：手机能完成上传、放大核对和修改；长任务有状态、取消和失败原因；记录每题耗时与人工修订时间；无模型连接时人工流程不受阻 |

关键验收细化：

- AC-06／AC-10：未知图片 ID、越界坐标、错误原图哈希或不属于当前资料集的引用被拒绝；引用合法但不支持结论时，家长可拒绝并记录原因。缺坐标的旧索引仅保留整图级引用，明确“区域待补”。
- AC-09：历史笔迹来源不明、作答日期未知和提示后完成三类记录都能保存，均不会被计成独立成功；将某条观察关联到作答时保留转换依据。
- AC-15：审核界面打开后另一操作修改题干／区域，旧界面的接受请求返回版本冲突；刷新并确认当前版本后才允许落库，不能只在界面显示警告而仍写入。
- AC-18：并发调用的预算预留必须原子执行，不能由多个任务同时花掉同一额度；超时未知费用保留预留并标记待结算。用量缺失不能按零费用释放额度；限额和币种规则见可行性评估。
- AC-19：首次启用云端及外发范围变化时展示供应商、数据类别与已知留存方式，由家长设置并保存外发配置的版本、设置者、确认时间、供应商／网关及已知上游；任务绑定配置并展示本批实际图片区域／文本范围。不逐题重复确认已有范围，但新增上游或扩大数据类别必须更新配置；agent 无权扩大。
- AC-19：家长关闭云处理后，尚未发送的排队任务及重试不再外发；每次实际发送前重新检查启用状态。已发出的请求与数据不能声称被撤回，迟到响应保留已外发标记，不触发新的外部调用。
- AC-19：原图、派生图、模型原始响应、运行日志和备份分别声明保留周期与删除行为；按配置测试到期处理、归档和删除。恢复旧备份时核对恢复点之后的删除记录；记录缺失时由家长核对后再开放资料，不能宣称旧备份自动包含后续删除。供应商端已发出数据的留存／删除能力单独说明，不能用本地删除成功宣称云端也已删除。

初始支持 JPEG／PNG；其他格式先明确拒绝或由单独转换入口处理。单文件和像素上限在上传实现时配置并测试，不沿用任意供应商的最大值作为应用默认值。

## 8. 验证数据与完成标准

先对现有 23 张照片按整页划分开发样本和保留样本，防止同页裁图同时用于调提示和最终评估。覆盖六组、密集分式、指数／符号、跨页、手写混排、擦除和原资料勘误；不将 81 条索引称为已有完整 OCR 真值。

人工补齐评估样本的题干、区域和期望分类。没有独立作答来源的照片只用于识别和证据边界测试，不能用于验证“掌握程度预测准确率”。

M1a：完成 AC-01～AC-05、AC-07～AC-10、AC-12、AC-15～AC-17、AC-20～AC-24 的人工／本地部分；AC-11 证明 AI 关闭时流程可用；AC-19 证明密钥保护和本地保留／删除规则。知识库、题库关联和个人档案先能人工维护；明确这些不是 AI 功能通过。

M1b：补齐 AC-06、AC-11、AC-18、AC-19 的模型调用、工具、预算与外发部分，以及 AC-21～AC-24 等场景的 AI 路径，包含知识草稿和手写过程评价。整体 M1 完成要求 P0 的 AC-01～AC-12、AC-15～AC-24 均有可复查的运行结果；旧索引覆盖率 100%，审核绕过和来源越界的固定反例全部拦截。识别、分类、解析和过程评价分别报告，不以 schema 合法率替代内容正确率。

对 AI 的产品价值，比较同一批样本人工录入与 AI 后修订的耗时、关键符号错误、漏题和误分类。样本小，报告计数和案例，不声称普遍精度。是否推广某模型依据后续基准，当前不设未经测量的“95% 准确率”承诺。

## 9. 需求评审结论与待定项

初步结论：范围在技术上可行；主要不确定性是中文数学照片识别、复杂解题正确性、修订成本和学习证据来源。使用模型草稿、程序检查和人工审核能使这些不确定性可观察，不会自动消除它们。

尚待用户偏好或实测确定：供应商／已有网关、每月和每批预算、题目图片外发范围、部署设备、公式支持集。它们不阻碍本轮需求文档与本地接口设计；实际付费调用前必须有可用配置和明确限额。
