### 首个实施任务 A1a：离线核心契约与合成关系验证

目标是让共享语义成为可执行的离线校验，先发现关系、版本与未知处理的矛盾，再选数据库承载。用户于 2026-10-02 同意进入此范围，由一个 luna6-worker 实施。代码及运行结果以 DEV_STATE 的最终验收记录为准；A1b 及容器实现另属后续阶段。

| 项目 | 范围 |
| --- | --- |
| 输入 | `docs/requirements.md` 第 5／7／8 节、`docs/core-data-contract.md` 全文及 CT-01～CT-10、复用矩阵；旧来源清单仅说明索引缺口，不读取照片或迁移历史资料 |
| worker 文件所有权（已执行） | 仅 `app/domain/__init__.py`、`app/domain/contracts.py`、`app/domain/validation.py`、`app/domain/serialization.py`、`tests/domain/test_contract_scenarios.py`、`tests/fixtures/domain/synthetic-v0.1.json`；如需新增依赖／项目配置先由主代理定范围 |
| 输出 | 带 schema 版本的结构定义，类型化引用和关系校验，明确错误结果，保留稳定 ID／修订的 JSON 往返；仅含虚构图像元数据、称呼及内容的合成样例和必要行为验证 |
| 不在任务内 | Web、Django／数据库迁移、候选复制／运行、真实图片读写、实际旧索引导入、渲染器迁移、OCR／API／agent、备份服务或部署 |
| 主代理所有权 | 共享语义和文档、范围／依赖决定、完整实际 diff 审查及独立运行验证；worker 不是唯一修改者，不得回退他人改动，遇到契约冲突先说明 |

验收条件：

1. 合成知识／方法／题型有独立 ID，题目跨页，节点→题目→原图及原图→题目→节点查询返回相同身份、版本和来源；拒绝错家庭、错哈希、越界坐标、错版本引用和父子环（CT-01、CT-07）。
2. 同题两次真实作答及各自评价分开，首次评价修改后保留前版；JSON 往返后作答、评价、修订及关系数量不变，不能按学习者＋题目合并（CT-02）。
3. 课堂、提示后完成、抄录、来源不明、空白、看不清及时间未知分别保留；未知档案观察不强制成为作答，不计独立成功；答案对过程错也分维度保存（CT-03、CT-04、CT-10）。
4. 勘误原文、依据、新使用内容和孩子错误分别存在，接受订正不重写旧题目／旧作答；缺题干或坐标的旧索引形状只保留待补，不能成为完整审核题（CT-05、CT-09）。
5. 纯函数比较预期版本与当前版本，迟到结果／旧审核请求返回 `stale` 或 `version_conflict`，不生成有效发布结果（CT-06）；数据库原子性留待 A1b。
6. 合成关系包完整往返；同包重复合并保持数量，同 ID 异内容返回冲突，引用缺失明确失败（CT-08）。这里只验元数据闭包和身份，不声称真实图像恢复已通过。
7. 主代理阅读所有改动及合成样例，独立运行行为验证，检查无个人数据和隐式网络调用，再更新 DEV_STATE。A1a 通过不代表 A1b、M1a 或候选适配通过，不自动提交／推送。
