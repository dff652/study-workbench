# design.md 前端接入评估与实施建议

日期：2026-10-08（Asia/Shanghai）。结论：**适合引入为设计规范与开发校验工具**，兼容当前前端；先形成项目自己的设计约定，再做代表页面试点。当前产品仍为半成品，设计规范统一不能代替任务流程完善和真实用户验收。本文保留调研与隔离CLI验证；用户随后批准实施，应用接入、页面改进及实际验证的当前状态见[本轮实施回执](design-md-implementation-20261008.md)。

后续产品问题、任务状态继续维护在[整改主基线](learning-system-ux-remediation-baseline-20261006.md)、[后续整改任务](learning-system-acceptance-follow-up-20261006.md)及[实施回执](learning-system-follow-up-implementation-20261007.md)。本建议补充设计工具接入方案，不重新关闭已登记的产品问题。

## 项目能力与适用范围

[Google Labs design.md](https://github.com/google-labs-code/design.md)通过YAML保存颜色、字体、间距及组件等设计值，通过Markdown说明视觉意图；CLI提供规范校验、版本比较和导出。它是开发参考与工具，不提供现成学习页面。上游规范标记为alpha，采用Apache 2.0许可，接入应固定版本并保留升级验证。[规范](https://github.com/google-labs-code/design.md/blob/9bf8eae67128b6cc55ad9bf86665767deb4c11cd/docs/spec.md)、[许可](https://github.com/google-labs-code/design.md/blob/9bf8eae67128b6cc55ad9bf86665767deb4c11cd/LICENSE)。

| 当前需要 | 能提供的帮助 | 仍需项目实现与验收 |
| --- | --- | --- |
| 颜色、字体、间距和状态不统一 | 可供开发者与编码代理共同读取的设计约定 | 组件、原生业务模板和实际页面贯彻规范 |
| 改版后样式继续漂移 | 设计值比较、失效引用检查、部分颜色对比度检查 | 规范与源码一致性、所有状态的浏览器检查 |
| 页面过长、布局失衡、主动作不清楚 | 用文字描述页面职责、布局和动作原则 | 导航、模块编排、自然高度和交互实现 |
| 练习、评价、复测与来源难理解 | 记录术语和证据呈现原则 | 业务语义、权限、版本关联及保存正确性 |
| 可用产品差距较大 | 帮助后续整改保持一致 | 学生／家长实际任务、Word实开及真实效果 |

视觉方向应围绕中文学习、原图对照、清晰任务和可展开的证据；不照搬上游示例的配色或装饰风格。一次成功、计划完成、生成答案都不转成长期掌握。未知、待核实、已确认、错误与已完成分别表达，状态必须有文字，不能只靠颜色。

## 当前前端兼容性

当前[前端依赖](../../frontend/package.json)为React 19、Tailwind 4、Vite和TypeScript，按钮与Badge采用本地shadcn风格组件。上游CLI 0.4.0要求Node至少18；当前本机Node 20.19.2可运行。上游支持Tailwind 4 CSS、Tailwind 3 JSON、CSS变量和DTCG导出。[包定义](https://github.com/google-labs-code/design.md/blob/9bf8eae67128b6cc55ad9bf86665767deb4c11cd/packages/cli/package.json)、[导出实现](https://github.com/google-labs-code/design.md/blob/9bf8eae67128b6cc55ad9bf86665767deb4c11cd/packages/cli/src/commands/export.ts)。

关键接入点是[主题](../../frontend/src/styles/theme.css)、[基础样式](../../frontend/src/styles/index.css)、[工作区样式](../../frontend/src/features/workspace/page.css)、[按钮](../../frontend/src/components/ui/button.tsx)和[Badge](../../frontend/src/components/ui/badge.tsx)，以及嵌入的原生业务页面。保留当前React／Django／PostgreSQL架构；CLI作为开发工具使用，正式业务数据仍由现有后端管理。

**导出需要映射层。** 现有主题通过`--primary`等语义变量、`.dark`覆盖和`@theme inline`别名工作；上游导出直接生成`--color-primary`等值。隔离样例还将`primaryForeground`原样导出为驼峰变量，不能匹配现有`--color-primary-foreground`。样例中的OKLCH颜色被输出为十六进制，不能假定导出保留原始表示。字体串也需核对是否形成正确的CSS字体列表。自动覆盖`theme.css`会绕过既有主题关系，不能据此直接上线。

建议由规范定义语义设计值，以显式映射生成或核对现有变量；亮色／深色分别明确取值与对比度，React和原生模板使用同一语义。Web阅读与PDF／Word打印规范分开，不能由Web主题重写打印版式。首轮保持现有颜色，再逐项调整，避免工具接入与全站改版混成一次变更。

## 接入任务与验收标准

以下保留调研时的任务与验收标准；用户随后批准按清单执行。实现、工程验证及真实用户结果分别回填到[实施回执](design-md-implementation-20261008.md)，不把所有验收标准都标为已通过。

| 任务 | 交付与依赖 | 完成标准 |
| --- | --- | --- |
| DM-01 项目设计规范 | 根目录`DESIGN.md`，提取主基线的字号、间距、宽度、动作及状态原则；链接现有业务规则 | 七域职责、学生／家长呈现、证据展开、各类空状态有明确原则；设计值无失效引用；不新增无依据指标 |
| DM-02 主题映射与约束 | 依赖DM-01；显式映射规范与现有语义变量，区分亮／暗、Web／打印 | 名称、字体列表、颜色转换和深色覆盖逐项验证；按钮／Badge／原生页面无主题分叉；打印内容与原版式不受影响 |
| DM-03 开发校验 | 依赖DM-01／02；固定0.4.0为开发依赖及锁文件，提供lint、报告拦截和一致性检查 | 失效引用与低对比度反例均失败；正常规范通过；过时生成值可检测；生产浏览器包不包含CLI |
| DM-04 学习总览试点 | 依赖DM-01／02；突出当前对象、下一步与最近成果，证据渐进展开 | 1280／1440／1920及200%缩放无横向任务阻碍；少量记录无双栏巨大留白；学生10秒指出对象／任务／主动作，实际测试登记结果 |
| DM-05 资料整理试点 | 依赖DM-01／02；来源／编辑主次清楚，列表与当前对象稳定，错误及保存状态可辨 | 缩放／旋转后选区仍对应原图；切页、返回和取消离开不丢输入；草稿与可练习题边界清楚；失败可重试 |
| DM-06 家庭成员试点 | 依赖DM-01／02；成员、角色、关联学习者、权限、状态与操作清楚 | 有成员时先显示列表，添加表单按需打开；已有权限契约保持，不能伪造权限或最近活动；无关联／无权限状态有明确解释 |
| DM-07 七域推广与真实验收 | 依赖DM-03～06试点复核；推广到知识题库、档案、进度复测、文档中心及其他设置页 | 按主基线逐页验收八维与关键状态；连续任务不丢对象／版本／输入；目标用户、内置客户端及Word结果分别登记，未测保持未测 |

建议顺序：继续已同意的真实小批次验收并收集缺陷 → DM-01～03建立规范及约束 → DM-04～06代表页面试点 → 根据反馈推进DM-07。试点只覆盖前端职责，不改变来源、作答事件、评价修订或复测关联的真实性。后续若分配Luna6实施，按文件边界分工；主代理审查完整差异、独立验证并收口，业务规则和最终验收由主代理负责。

部署需针对最终候选重新核对构建、备份、恢复和双入口运行；调研阶段没有部署，后续实施状态以实施回执为准。文档本地提交，后续仍由用户统一手动push。

## 正式小批次验收准备

用户已提出使用飞牛指定目录的“几何综合1”，允许从中选题。该资料适合验收原图对照、题面图、解析、公式与文档路径；拟选两道代表题。完整目录与学习者尚未提供，Word客户端也未指定；已有几何小样副本不能直接认定为这份资料。已继续询问目录与学习者，不从浏览器当前URL推断验收范围，不新增真实作答或测试成绩。

对象明确后，先核对归属、实际日期／完成条件与每项新增记录的真实内容，检查存储空间并创建可恢复的配套备份，再执行原图／题目 → 文档 → 实际作答 → 人工评价 → 复测关联的小批次路径。若尚未真实发生复测，只准备计划并保留未测，不补造复测成功。小批次通过也不代替[目标用户与客户端门槛](learning-system-target-user-acceptance-20261007.md)。
