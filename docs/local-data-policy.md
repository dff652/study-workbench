# 本机数据保留、人工耗时与退役账本

本说明补充 [容器恢复步骤](container-deployment.md) 中的本机文件生命周期边界。个人资料仍位于受保护的 `SWB_DATA_ROOT` 和数据库；Retirement ledger 是退役快照清单，不是完整备份，也不能代替数据库与数据卷的配套备份。

## 按类型的默认生命周期

“本机数据与人工记录”页面展示以下策略。应用只提供导出文件的归档／退役命令；它不会自动清理原图、派生文件、领域历史或备份。

| 类型 | 默认保存 | 归档与退役 |
| --- | --- | --- |
| 原始照片 | 在私有资料卷原样保留，原件不被裁切、遮白或增强覆盖。 | 随资料卷进入配套备份；不自动归档或退役，当前没有原图自动删除流程。 |
| 派生文件与预览 | 旋转预览、裁切、手动遮白和增强结果独立于原图保存，并记录来源、参数和有损说明。 | 随资料卷进入配套备份；不自动归档或退役。任何后续退役都必须保留原图及派生追溯记录。 |
| 领域历史 | 题目、知识、作答、评价等修订作为追加历史保留。 | 随数据库进入配套备份；没有自动归档或退役操作。 |
| AI 响应 | `ModelRun` 的响应、工具结果、用量和状态保存在本机数据库。 | 随数据库进入配套备份；没有自动归档或退役操作。供应商是否另存副本按配置记录，未说明时为未知。 |
| 运行日志 | worker 输出任务编号、状态和错误码，不输出响应正文或密钥。 | 项目没有设置日志轮转期限；主机或容器运行环境负责轮转和删除，实际期限未知。 |
| 备份 | 每次备份把数据库与整个私有资料卷写入一个新的独立目录，已有目标会被拒绝覆盖。 | 应用不自动归档或删除旧备份；备份位置、保留期和退役由运维者单独管理。 |
| 导出 | 默认保留导出文件、快照行及历史元数据，不自动归档或退役。 | 只有所有者显式维护时才会归档／退役指定导出目录；退役前校验并保留归档副本和账本。 |
| 供应商侧副本 | 每个配置版本保存供应商／网关、连接路径、已知上游名单或显式未知、留存说明或显式未知及确认者／时间。 | 本应用没有供应商删除接口；供应商侧删除状态保持未知，不能把本机退役记作外部删除成功。 |

派生文件的应用数据记录为不可改写历史，不替代原图。当前退役账本和 CLI 只管理导出快照目录；上述其他类型均不受导出退役策略影响。若运行环境配置了日志或备份清理，应单独检查该环境策略及其对恢复能力的影响。

## 默认保留与可配置策略

每个家庭的默认策略不设置自动归档或退役期限。家庭所有者可在“本机数据与人工记录”页面进入保留策略并追加版本；保留期限以导出快照创建时间计天。退役期限必须不早于归档期限。保存策略只定义到期候选；它不会自行删除文件。所有者还必须显式运行 `--execute`。

退役只处理由 `ExportSnapshot.storage_key` 指定的 `prints/<家庭散列>/...` 导出目录。执行前，程序校验快照清单及每个文件的哈希，把完整目录复制到受控的 `retention-archive/<家庭散列>/...`，校验归档副本与原件一致，并追加不可变归档和退役记录，然后在数据库事务提交后移除原导出目录。数据库快照行和历史元数据仍保留，应用可据退役记录返回不可用状态。归档和账本也保留，因此这项操作不宣称永久删除。

原始照片、派生文件、题目和作答等领域修订历史、模型提案、运行日志和数据库／资料备份不会被此操作触及。供应商留存按配置记录；若没有已知说明则保持未知。本机退役不会向供应商发起删除请求，也不证明外部副本已删除。

## 预览和显式维护命令

先确认配置指向私有资料根目录，并以家庭所有者账号运行。命令要求提供精确家庭 ID 和活动所有者账号 ID；所有文件目标从数据库记录生成，命令不接受路径参数。默认只预览，不修改文件或数据库：

```bash
.venv/bin/python scripts/manage_private_retention.py \
  --household '家庭 ID' --owner-id '所有者账号 ID'
```

源码命令须使用显式配置的目标数据库和 `SWB_DATA_ROOT`。36 测试服务应在其现有容器中执行，只预览示例为：

```bash
docker compose --env-file data/runtime-36/compose.env \
  --project-name study-workbench-36 -f compose.yaml exec web \
  python scripts/manage_private_retention.py \
  --household study-workbench-36 --owner-id '本机所有者账号 ID'
```

账号 ID 在本机受保护账号文件或已认证管理命令中查询；它不是密码。后续动作使用相同容器前缀。`--dry-run` 与执行动作互斥，不能同时使用。

只有策略已检查、候选范围和备份状态明确后，才使用 `--execute --reason '维护依据'` 执行到期策略：

```bash
.venv/bin/python scripts/manage_private_retention.py \
  --household '家庭 ID' --owner-id '所有者账号 ID' \
  --execute --reason '按已审核的家庭保留策略维护'
```

也可显式归档或退役单个数据库快照 ID：使用 `--archive-snapshot ID` 或 `--retire-snapshot ID` 并提供原因。退役仍会先验证和保留归档副本。操作日志只记录账号、家庭、快照及哈希元数据，不写入自由文本原因。

所有者可按需导出或校验退役账本：

```bash
.venv/bin/python scripts/manage_private_retention.py \
  --household '家庭 ID' --owner-id '所有者账号 ID' --export-ledger

.venv/bin/python scripts/manage_private_retention.py \
  --household '家庭 ID' --owner-id '所有者账号 ID' \
  --verify-ledger '64 位小写十六进制账本 ID'
```

导出账本写入 `SWB_DATA_ROOT/retention-ledgers/<家庭散列>/`，目录权限为 `0700`、文件权限为 `0600`。校验只读取所选账本，不扫描用户目录，也不会修复或更改数据库。输出列出账本相对数据库的缺失、额外和不匹配快照；有差异时停止恢复验收，先调查备份配对和数据状态。

账本有差异时命令退出码为 2；完全匹配才返回 0。账本哈希、结构或路径无效同样拒绝通过。

## 配套备份和恢复

执行策略变更前，按[容器备份与恢复说明](container-deployment.md)保存数据库和全部相关私有数据卷的配套备份，并记录备份标识。不要把账本导出误认为完整备份；它不包含题目修订、作答、评价、原始照片或模型配置。

每次执行到期退役后，将最新账本按现有受保护备份流程另行保存到与运行数据卷分开的备份位置，并记录它的 `ledger_id`。这份独立账本应晚于待恢复的数据库备份；只检查旧备份中随数据卷保存的账本不能发现该备份之后发生的退役。

恢复时先在隔离状态还原数据库与匹配的数据卷，再把最新独立账本放回该家庭受控账本目录：将文件置于导出的相对位置 `retention-ledgers/<家庭散列>/ledger-<ledger_id>.json`，目录权限 `0700`、文件权限 `0600`。这个位置由账本 ID 和家庭 ID 确定，命令不接收任意文件路径。之后运行 `--verify-ledger <ledger_id>`。如果使用较旧数据库备份，最新账本可能列出该备份里不存在的后续退役；程序会将它们报告为缺少项，所有者应核对较新的独立账本和恢复备份的时间边界，再决定是否继续开放恢复服务。账本不存在、哈希不符或内容与恢复数据库不匹配时，保留现场并调查备份来源；该命令不会自动删除多余数据、回写数据库或改选另一份账本。

恢复整个系统仍需数据库备份、原图／派生文件卷、打印导出／归档卷及必要的账户／模型配置备份。`verify_retirement_ledger` 只核对退役快照记录的元数据和登记哈希，不验证完整系统恢复，也不证明外部供应商数据已删除。

## 人工耗时记录

家庭所有者或审核者可打开 `operations:work_timing_new` 页面，为当前已发布题目版本追加一条估计耗时。可选的作答必须是该家庭当前、有效且引用同一精确题目版本的作答修订。记录类型明确区分“手工录入”和“模型结果人工修订”；秒数和依据由记录者填写并作为不可变历史保存。

这些记录是人工估计，不代表精确测量。模型实际运行时间仍使用独立的模型任务记录；没有后台自动计时，不会由处理时间推断孩子的作答时长或掌握程度。
